## What shipped

`docs/card-scripts/drafts/fdn.md` §7 (lines 71, 73):

## What didn't ship (and why)

- **Cultivator's Caravan** (`{T}: Add one mana of any color.` + crew).
  The card has **two** blockers per fdn.md line 71 + line 246:
  AddMana (✅ shipped) + Crew (not shipped). Shipped only the mana
  side would be misleading. Defer to the Crew lane.
- **Ruby, Daring Tracker** (add mana + check power-4). Two blockers
  per fdn.md line 117 + line 120. The "add mana" part is buildable
  now; the "check power 4 or greater" needs an unbuilt `if`-clause
  form (function-of-state predicate on `if` triggers). Defer.

## Known limit: once_per_turn on mana abilities

`Three Tree Mascot` declares `limit: "once_per_turn"` on its
activated ability. This limit is honored by `activateAbility` (the
generic path, issue #2496, CR 602.5b) but **not yet** by
`activateManaAbility` (no `activationLimit` gate in
`mana-production.ts`). The schema comments at `schema.ts` mark this
as a future-lane item.

End-to-end correctness for Three Tree Mascot requires either:

- (a) `activateManaAbility` learns `activationLimit`, OR
- (b) Three Tree Mascot's `{T}` ability routes through
  `activateAbility` (which already enforces the limit).

For this iteration, the JSON shape correctly declares the intent;
the test exercises the multi-option choice resolution via
`activateManaAbility` and adds 1 R as expected. The once-per-turn
gate is **declared, not enforced** on the mana-ability path; the
card's correctness depends on a future lane.

## Process notes

- `cards/*.json` carry the canonical card metadata + script body;
  `cards/index.generated.ts` (gitignored) is regenerated by
  `npx tsx scripts/build-card-script-index.ts`. The committed source
  of truth is the JSON.
- `CardScriptSchema` (`schema.ts:4819`) is strict — it rejects
  metadata keys (`mana_cost`, `type_line`, `power`, `toughness`)
  at the top level. Card JSONs should include only the script-shape
  fields (`name`, `oracle`, `activated`, `triggered`, etc.). Card
  metadata is stored elsewhere (the card-database path).
- For new card-script work, follow the wave45 cadence: schema →
  engine → card scripts (one card per blocker) → tests → ratchet →
  handoff doc → PR.
