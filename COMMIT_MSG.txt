feat(card-scripts): exile target player's graveyard (#2594 follow-up)

The drafter has 1 FDN card wanting this — Angel of Finality (FDN
#136, "Flying. When this creature enters, exile target player's
graveyard."). The current `Exile` op's `fromZone` only handles
single-card graveyard exile (lane 10). This lane adds
`"opponent_graveyard"` to the `fromZone` enum and threads the
engine's `effectTargetLegal` / `applyEffect` to sweep every card
in the chosen player's graveyard. The chosen player is narrowed
by `effect.controller` (default: opponent).

## Schema
- `ExileSchema.fromZone` accepts the new
  `"opponent_graveyard"` value alongside the existing
  `"battlefield"` / `"graveyard"`.

## Engine
- `interpret.ts` `case "Exile":` — when `effect.fromZone ===
  "opponent_graveyard"`, the engine skips the single-target
  legality check (the target is narrowed by `effect.controller`)
  and iterates the chosen player's graveyard, calling
  `exileCard` for each match. `exileCard` already routes to the
  card's controller's exile zone.
- `script-guards.ts` `isTargetedEffect` — the `Exile` case
  returns false when `fromZone === "opponent_graveyard"` so
  `effectTargetCount` reads 0 and the dispatcher doesn't try to
  consume a target slot the script didn't request.
- `interpret.ts` `effectTargetLegal` — returns true for the
  sweep; the actual sweep ignores `target.targetId` and reads
  `effect.controller` instead.

## Sample card
- `cards/angel_of_finality.json`: "Flying. When this creature
enters, exile target player's graveyard." (controller: "opponent").

## Tests
4 new in `exile-player-grave.test.ts`:
- Angel of Finality script fixture declares
  `fromZone: "opponent_graveyard"` and `controller: "opponent"`
- end-to-end: the opponent's graveyard is empty after the
sweep; the exiled cards land in the controller's exile zone;
the controller's own graveyard is untouched
- end-to-end: `controller: "you"` sweeps the source controller's
own graveyard instead
- empty opponent graveyard is a no-op (no failure)
