## Pitfalls the next session should remember (updated from Wave 3)

- **Test count divergence** — the handoff's "first bump is usually off by 5–10" is real. My local `npm run ratchet:test-count` after Lane 1 reported 13395; CI's `check-test-count-docs` reported 13398 (3 more, from `it.each(files)` for the 232 card JSONs that I'd reset the index for). The fix: run `npm test --silent` and re-ratchet to pick up the live count. The `npm run ratchet:test-count` script uses `npm test --silent` internally, so the divergence was from a stale local `node_modules` (or a parallel PR that landed between my typecheck and the CI re-measure).

- **`z.lazy` recursion needs an explicit type alias** — the Wave 3 OR-filter lane (`#2605`) needed a `SearchLibraryFilterShape` type alias to break the cycle between the `z.object()` and `z.lazy()`. Without it, TS infers `any` and the `refine` callback loses its parameter type. The `as const` on the result of `z.lazy()` is also needed for `.array().min(1)` to typecheck.

- **Race with parallel PRs** — during Wave 3 every lane I tried to land had to be re-rebased because bot PRs and the user's other work kept landing on main. The pattern that worked: each lane rebases to current `origin/main` (not a frozen snapshot), re-runs `npx tsx scripts/build-card-script-index.ts` (the index wasn't in my commit but it gets regenerated by the `pretypecheck` hook), and re-runs the ratchet. Lane 3 needed 2 rebase attempts. Each rebase: ~3 minutes.

- **The Burnished Hart test in `card-scripts.test.ts` line ~5269** still has the one-land-only library setup from the Wave 2 workaround, but it's now a stale comment — `SearchLibrary.count: 2` is fully supported in the schema. Future cleanup.

- **Boros Charm's 3rd mode is now restored** (double strike, post-#2600). The 2nd mode still scripts as `target: "creature"` + `controller: "you"` instead of `target: "permanents_you_control"` (#2594 item 14, separate lane).

- **The `granted-keywords.ts` module still exports `clearGrantedKeywordsUntilEot` (deprecated name)** — unchanged from the Wave 2 handoff's warning.

- **Turbopack rejects symlinked `node_modules`.** When the worktree has no `node_modules` and main's was lost, `cp -al` from a previous worktree works only if the worktree still exists. Otherwise `npm ci` (~3 min) is the only option. The 2 worktrees I created this session had to do a fresh `npm ci`.
